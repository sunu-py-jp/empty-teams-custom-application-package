# 元の手順書からの主な修正

修正日：2026年9月30日。本文の14章構成、当社／お客様の役割分担、A・B・Cの試験区分を維持しました。

| 対象 | 修正内容 | 理由 |
|---|---|---|
| アプリ情報の照合 | マニフェストの`id`はExternal app IDと照合。カタログ側IDは別項目として記録 | IDの種類による誤判定を避ける |
| 管理者登録 | 登録前の既定利用範囲と、登録後の個別設定を確認。Aのみの場合も確認を実施 | 任意のユーザー追加試験を省略しても利用対象の管理を省略しない |
| 利用対象 | Aのみなら原則No one、A+Bなら指定テストユーザー／グループ。技術的な登録合格と運用上の完了を区別 | 登録成功とユーザーへの公開は異なるため |
| 管理方式 | アプリ中心の管理と、Teams／Microsoft 365の統合アプリ管理（UAM）を別々に確認 | 移行状況によって確認場所が異なるため |
| 修正パッケージ | 同一アプリはID維持、更新配布では`version`更新 | 既存アプリの更新として扱うため |
| 反映待ち | 結果に反映待ちを追加。変更日時・再確認日時を記録 | 設定反映前に失敗と判断しないため |
| タブ表示 | TeamsJS初期化・埋め込みの要件を補足。表示を合格条件に含めない方針を維持 | 通常のWebページはTeamsタブの実装要件を満たさない場合があるため |
| Developer Portal | App package editorのエラー確認と、Store向けApp validationを区別 | 読み込み・保存だけでは適合判定にならないため |
| 作業フォルダー | 作成済みGUID・アイコンを利用する手順、未設定値の差し替え手順を追加 | ZIP化直前の成果物から作業を再開できるようにするため |
| 圧縮 | Windows／Mac両方のコマンドを掲載。3ファイルだけを対象とし、既存ZIPの再利用を避ける | 余分な階層・補助ファイルの混入を避けるため |
| 検証記録 | IDの種類、管理方式、利用対象、変更時刻、後片付けを記録票に追加 | 結果の再確認と切り分けを可能にするため |

技術的な根拠のリンクは手順書14章にまとめています。実テナントの設定変更、登録、ユーザー追加は実施していません。
